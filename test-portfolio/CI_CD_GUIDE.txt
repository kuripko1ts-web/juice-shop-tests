================================================================================
1. ЩО ТАКЕ CI/CD?
================================================================================

CI (Continuous Integration) - безперервна інтеграція
- Автоматичний запуск тестів при кожному зміні коду
- Швидке виявлення помилок
- Автоматична перевірка коду перед злиттям

CD (Continuous Deployment) - безперервне розгортання
- Автоматичне розгортання після успішних тестів
- Швидкий release cycle

GitHub Actions - безкоштовний сервіс CI/CD від GitHub
- Інтегрований з GitHub
- Підтримує Linux, Windows, macOS
- Безкоштовний для public repositories

2. ПІДГОТОВКА ПРОЕКТУ
================================================================================

Крок 1: Створення .gitignore файлу
────────────────────────────────────────────────────────────────────────────
ЩО: Файл який вказує Git які файли ігнорувати
ПОЧИМУ: Не потрібно комітити node_modules, звіти, логи
ДЕ: test-portfolio/.gitignore

ЩО МІСТИТЬ .gitignore:
- node_modules/ (залежності npm)
- test-results/ (результати Playwright)
- playwright-report/ (HTML звіти)
- logs/ (лог файли)
- .env (змінні середовища)
- .DS_Store, Thumbs.db (системні файли)

ЯК СТВОРИТИ:
Створіть файл .gitignore в корені test-portfolio/ і додайте вміст з прикладу.

Крок 2: Ініціалізація Git репозиторію
────────────────────────────────────────────────────────────────────────────
Відкрийте термінал в папці test-portfolio/:

git init
git add .
git commit -m "Initial commit: Add test portfolio with CI/CD"

Крок 3: Створення GitHub репозиторію
────────────────────────────────────────────────────────────────────────────
1. Перейдіть на https://github.com
2. Натисніть "New repository"
3. Введіть назву репозиторію (наприклад: juice-shop-test-portfolio)
4. Виберіть "Public" або "Private"
5. Не ставте галочку "Initialize this repository with README"
6. Натисніть "Create repository"

Крок 4: Підключення локального репозиторію до GitHub
────────────────────────────────────────────────────────────────────────────
Після створення репозиторію GitHub покаже команди для підключення:

git remote add origin https://github.com/YOUR_USERNAME/YOUR_REPO.git
git branch -M main
git push -u origin main

Замініть YOUR_USERNAME/YOUR_REPO на ваші дані.

3. СТРУКТУРА GITHUB ACTIONS
================================================================================

Шлях до workflow файлів:
.github/workflows/

Структура:
test-portfolio/
├── .github/
│   └── workflows/
│       ├── ui-tests.yml      (workflow для UI тестів)
│       └── api-tests.yml     (workflow для API тестів)

Кожен .yml файл = окремий workflow
- Може запускатися незалежно
- Має свої тригери запуску
- Має свої налаштування

================================================================================
4. РОЗБІР UI-TESTS.YML
================================================================================

name: UI Tests
────────────────────────────────────────────────────────────────────────────
Назва workflow яка відображається в GitHub Actions tab

on:
  push:
    branches: [ main, master, develop ]
  pull_request:
    branches: [ main, master, develop ]
  workflow_dispatch:
────────────────────────────────────────────────────────────────────────────
ТРИГЕРИ ЗАПУСКУ:
- push: запускається при push в вказані гілки
- pull_request: запускається при створенні PR
- workflow_dispatch: дозволяє ручний запуск з GitHub UI

jobs:
  ui-tests:
    runs-on: ubuntu-latest
────────────────────────────────────────────────────────────────────────────
JOB:
- ui-tests: назва job
- runs-on: ОС на якій запускаються тести (ubuntu-latest, windows-latest, macos-latest)

steps:
────────────────────────────────────────────────────────────────────────────
STEPS: кроки виконання job

Step 1: Checkout code
- name: Checkout code
  uses: actions/checkout@v3
────────────────────────────────────────────────────────────────────────────
Клонує репозиторій в GitHub Actions runner

Step 2: Setup Node.js
- name: Setup Node.js
  uses: actions/setup-node@v3
  with:
    node-version: '18'
────────────────────────────────────────────────────────────────────────────
Встановлює Node.js версії 18

Step 3: Install dependencies
- name: Install dependencies
  working-directory: ./ui-tests
  run: npm install
────────────────────────────────────────────────────────────────────────────
Встановлює залежності з package.json в папці ui-tests

Step 4: Install Playwright browsers
- name: Install Playwright browsers
  working-directory: ./ui-tests
  run: npx playwright install --with-deps chromium
────────────────────────────────────────────────────────────────────────────
Встановлює браузер Chromium для Playwright

Step 5: Start Juice Shop server
- name: Start Juice Shop server
  working-directory: ../juice-shop
  run: |
    npm install
    npm start &
    sleep 15
────────────────────────────────────────────────────────────────────────────
Запускає Juice Shop сервер в фоні (&) і чекає 15 секунд

Step 6: Run Smoke tests
- name: Run Smoke tests
  working-directory: ./ui-tests
  run: npx playwright test smoke.spec.js
────────────────────────────────────────────────────────────────────────────
Запускає smoke тести

Step 7: Run Regression tests
- name: Run Regression tests
  working-directory: ./ui-tests
  run: npx playwright test reg.spec.js
────────────────────────────────────────────────────────────────────────────
Запускає регресійні тести

Step 8: Upload Playwright Report
- name: Upload Playwright Report
  if: always()
  uses: actions/upload-artifact@v3
  with:
    name: playwright-report
    path: ui-tests/playwright-report/
    retention-days: 30
────────────────────────────────────────────────────────────────────────────
if: always() - завантажує навіть якщо тести провалилися
Зберігає HTML звіт на 30 днів

Step 9: Upload test results
- name: Upload test results
  if: always()
  uses: actions/upload-artifact@v3
  with:
    name: test-results
    path: ui-tests/test-results/
    retention-days: 30
────────────────────────────────────────────────────────────────────────────
Зберігає результати тестів на 30 днів

6. ЯК ЗАПУСТИТИ CI/CD
================================================================================

Автоматичний запуск:
────────────────────────────────────────────────────────────────────────────
1. Зробіть зміни в коді
2. Закомітьте: git add . && git commit -m "message"
3. Запуште: git push
4. GitHub Actions автоматично запустить workflow

Ручний запуск:
────────────────────────────────────────────────────────────────────────────
1. Перейдіть в GitHub репозиторій
2. Натисніть "Actions" tab
3. Виберіть workflow (UI Tests або API Tests)
4. Натисніть "Run workflow"
5. Виберіть гілку і натисніть "Run workflow"

Перегляд результатів:
────────────────────────────────────────────────────────────────────────────
1. Перейдіть в GitHub репозиторій
2. Натисніть "Actions" tab
3. Клікніть на workflow run
4. Перегляньте логи кожного step
5. Завантажте artifacts (звіти)

7. ПОШУК НЕСПРАВНОСТЕЙ
================================================================================

Проблема: Workflow не запускається
────────────────────────────────────────────────────────────────────────────
Рішення:
- Перевірте що файл .yml в правильній папці (.github/workflows/)
- Перевірте синтаксис YAML (відступи важливі!)
- Перевірте що гілка в on: branches: існує

Проблема: Тести падають з "Connection refused"
────────────────────────────────────────────────────────────────────────────
Рішення:
- Збільште sleep time після npm start (наприклад, sleep 20)
- Перевірте що Juice Shop встановився коректно
- Перевірте порт (за замовчуванням 3000)

Проблема: "Module not found"
────────────────────────────────────────────────────────────────────────────
Рішення:
- Перевірте що package.json існує
- Перевірте що npm install виконався успішно
- Перевірте working-directory в workflow

Проблема: Playwright browser not found
────────────────────────────────────────────────────────────────────────────
Рішення:
- Додайте step: npx playwright install --with-deps chromium
- Перевірте що runs-on: ubuntu-latest (потрібен для Playwright)

Проблема: Artifacts не завантажуються
────────────────────────────────────────────────────────────────────────────
Рішення:
- Перевірте що path вказаний коректно
- Перевірте що if: always() додано
- Перевірте що папка існує після запуску тестів

================================================================================
8. ОПЦІОНАЛЬНІ НАЛАШТУВАННЯ
================================================================================

Паралельний запуск тестів:
────────────────────────────────────────────────────────────────────────────
Додайте в workflow:

strategy:
  matrix:
    shard: [1, 2, 3]
  fail-fast: false

run: npx playwright test --shard=${{ matrix.shard }}/3

Schedule runs (за розкладом):
────────────────────────────────────────────────────────────────────────────
Додайте в on:

on:
  schedule:
    - cron: '0 9 * * 1'  # Кожен понеділок о 9:00

Секрети (Secrets):
────────────────────────────────────────────────────────────────────────────
1. Settings → Secrets and variables → Actions
2. New repository secret
3. Назва: BASE_URL
4. Значення: http://localhost:3000

Використання в workflow:
env:
  BASE_URL: ${{ secrets.BASE_URL }}

Нотифікації (Slack/Discord/Email):
────────────────────────────────────────────────────────────────────────────
Додайте step після тестів:

- name: Notify on failure
  if: failure()
  uses: 8398a7/action-slack@v3
  with:
    status: ${{ job.status }}
    text: 'Tests failed!'
  env:
    SLACK_WEBHOOK_URL: ${{ secrets.SLACK_WEBHOOK }}

9. ЛІЧИЛЬНИКИ ТА МЕТРИКИ
================================================================================

GitHub Actions показує:
- Кількість успішних/провалених runs
- Час виконання workflow
- Кількість artifact завантажень
- Історію запусків

Додаткові метрики можна додати через:
- GitHub Insights
- Third-party integrations (SonarQube, Codecov)
- Custom reporting

10. НАСТУПНІ КРОКИ
================================================================================

Після базової налаштування:

5. Інтегруйте з issue tracker (Jira, GitHub Issues)
6. Додайте performance tests
7. Налаштуйте deployment після успішних тестів
